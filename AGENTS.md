# AGENTS.md

Context for AI coding agents working in this repository.

## What this app is

RecorderApp (`com.eva.recorderapp`) is an Android audio recorder with:

- Recording over multiple codecs (AAC, AMR, Opus) at different qualities, with background recording,
  notification controls, phone-call handling and optional location tagging.
- A built-in player (Media3/ExoPlayer with media notification), real-time amplitude visualization
  while recording and playing.
- An in-app audio editor to trim/cut sections.
- Categories, bookmarks (exportable to CSV), and trash management for recordings.
- On-device speech-to-text transcription using Vosk models.
- Home-screen widgets (Glance) and app shortcuts.
- Onboarding, plus settings for audio/transcription preferences.

## Tech stack

- **Language**: Kotlin, JVM target 17.
- **UI**: Jetpack Compose + Material 3, single-Activity, Navigation Compose. No XML layouts/screens.
- **DI**: Hilt everywhere (`@HiltAndroidApp` in `app`; every library module owns its Hilt modules in
  a `di/` package).
- **Playback/editing**: Media3 (ExoPlayer, session, transformer, effects).
- **Persistence**: Room (metadata DB) + DataStore (Preferences and Proto/protobuf for settings).
- **Background**: WorkManager with `HiltWorkerFactory` (trash cleanup, path correction workers).
- **Transcription**: Vosk (`data/transcribe`), which uses the Ktor client (via the `ktorLibs`
  version catalog) to download models.
- **Widgets**: Glance.
- **Build**: AGP 9, Gradle wrapper 9.x, configuration cache + build cache enabled. All versions live
  in `gradle/libs.versions.toml`.
- **Sdk**: `minSdk 29`, `compileSdk/targetSdk 37`.

## Module architecture

Five layer groups, defined in `settings.gradle.kts`:

| Group              | Modules                                                                                                                                                                        | Package convention            |
|--------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------|
| `:app`             | The application module                                                                                                                                                         | `com.eva.recorderapp`         |
| `:core:*`          | `core/ui` (shared composables, theme, nav utils), `core/utils` (Kotlin JVM helpers)                                                                                            | `com.eva.ui`, `com.eva.utils` |
| `:data:*`          | `recordings`, `recorder`, `player`, `editor`, `bookmarks`, `categories`, `database`, `datastore`, `location`, `transcribe`, `interactions`, `use_case`, `visualizer`, `worker` | `com.eva.<module>`            |
| `:feature:*`       | `recorder`, `recordings`, `player`, `player-shared`, `editor`, `categories`, `settings`, `widget`, `onboarding`                                                                | `com.eva.feature_<name>`      |
| `:testing:runtime` | `HiltTestRunner` used as the instrumentation runner by all `androidTest` setups                                                                                                | `com.eva.testing.runtime`     |

Rules:

- **Dependency direction**: `app` -> `feature`/`data` -> `core`. Feature modules depend on `data`
  modules and `core`, never the reverse. `data` modules never depend on `feature` modules. The
  generated graph lives in `module_graph.md` (regenerated by the `module-grapher` plugin).
- **`data:*` module internals**: `domain/` (interfaces + models, e.g.
  `domain/provider/*Repository*`, `domain/models`), `data/` (implementations, e.g.
  `*RepositoryImpl`), `di/` (Hilt modules binding impl to interface), plus module-specific folders
  (`task`, `wrapper`, etc.).
- **`feature:*` module internals**: `screen/` (screen composable + ViewModel), `composable/`
  (smaller composables), `viewmodel/`, `util/`. ViewModels use Hilt injection and expose state via
  Compose state/flows.
- **`data:use_case`** holds shared use-cases/factories that compose several repositories.

## Build and test

```bash
./gradlew assembleDebug                 # debug APK (what CI builds on push/PR to main)
./gradlew test                          # JVM unit tests (sparse; MockK + Turbine on the classpath)
./gradlew connectedDebugAndroidTest     # instrumented tests (needs device/emulator)
./gradlew :data:datastore:connectedDebugAndroidTest   # one module's instrumented tests
```

- Most tests are **instrumented** (`src/androidTest`): datastore repositories, database migrations,
  bookmarks, categories, interactions. The shared `HiltTestRunner` from `testing/runtime` is set as
  the instrumentation runner by the `recorderapp-android-library` convention plugin itself, and test
  Hilt modules live next to them (e.g. `DatabaseTestModule`).
- CI (`.github/workflows/`) builds `assembleDebug` on pushes/PRs to `main`, and runs instrumented
  tests on an API 36 `google_apis` x86_64 emulator.
- Gradle needs network for the first sync; `local.properties` (SDK path) is gitignored.

## Code style

- **Tabs for indentation** (Kotlin official code style, set in `gradle.properties`). Match existing
  files.
- Follow the existing `domain/`-interface + `data/`-implementation + `di/`-binding pattern when
  adding repositories or providers.
- New user-facing strings go in `src/main/res/values/`; localized copies exist in `values-bn`
  (Bengali) and `values-hi` (Hindi) — the app ships only `en`, `bn`, `hi`
  (`androidResources.localeFilters` in `app/build.gradle.kts`).
- Compose compiler stability: domain models are listed in the root `stability_config.conf`. When you
  add a new domain model that Compose reads, add its package there.
- New module? Apply the convention plugins from `build-logic` (e.g.
  `alias(libs.plugins.recorderapp.android.library)`, `recorderapp.hilt`, `recorderapp.room`,
  `recorderapp.protobuf`, `recorderapp.compose.compiler`) instead of hand-writing `android {}`
  blocks; register the module in `settings.gradle.kts`.
